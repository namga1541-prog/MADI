## 2. 개인정보 흐름

```
[학부모/치료사 입력]
    ↓
[클라이언트 PWA — XSS 방어, 16px font, TLS]
    ↓ (https, httpOnly cookie)
[Supabase Edge Functions — JWT 검증, RLS, rate limit]
    ↓
[Supabase Postgres — RLS, 암호화 at rest]
    ↓ (필요 시)
[Anthropic API — 임시 처리 후 즉시 폐기 계약]
```

## 3. 위험 분석

| ID | 위험 시나리오 | 발생 가능성 | 영향도 | 종합 |
|----|--------------|:----------:|:------:|:----:|
| R1 | admin 권한자 내부자 위협 (타 센터 데이터 조회) | 낮음 | 중 | 🟡 |
| R2 | 학부모 계정 탈취 (피싱) | 중 | 중 | 🟡 |
| R3 | Anthropic API 키 유출 → 비용 폭주 | 낮음 | 중 | 🟢 |
| R4 | SQL Injection / XSS | 낮음 | 높음 | 🟢 |
| R5 | Supabase 장애 → 가용성 손실 | 중 | 중 | 🟡 |
| R6 | 만 14세 미만 동의 누락 | 중 | 높음 | 🔴 |
| R7 | 직원 단순 실수(스크린샷 공유 등) | 높음 | 중 | 🟠 |
| R8 | 백업 데이터 유출 | 낮음 | 높음 | 🟡 |

## 4. 위험 완화 대책 (현재 적용)

| ID | 대책 | 적용 위치 |
|----|------|----------|
| R1 | RLS center_id 격리, 감사 로그(madi_audit_log), madi_settings SELECT 로깅 | DB / api Edge Function |
| R1 | 강제 로그아웃(session_revoked_at), 2FA(TOTP) | login + totp 함수 |
| R2 | bcrypt 12 round, 5회 실패 30분 잠금, httpOnly+Secure cookie | login 함수 |
| R3 | Edge Function env var (DB에서 분리), Anthropic 사용량 알림 | ai-proxy + console |
| R4 | escHtml 일관 적용, CSP, encodeURIComponent, 테이블 화이트리스트 | 전체 |
| R5 | 오프라인 폴백 페이지(offline.html), Service Worker 캐시 | sw.js |
| R6 | privacy.html 제2조의2 명시, 계약 시 보호자 동의서 수령 | 약관 / 운영 |
| R7 | 직원 교육(매년), 스크린 잠금 의무화 | 운영 |
| R8 | Supabase 백업 암호화(default), 백업 접근 권한 superadmin 한정 | Supabase 콘솔 |

## 5. 잔여 위험 (수용 / 모니터링)

| 위험 | 수용 사유 | 모니터링 방법 |
|------|----------|--------------|
| Anthropic 으로 데이터 임시 전송 | 계약상 즉시 폐기·미학습 보장, AI 기능 본질에 필수 | DPA 갱신, 사용량 모니터링 |
| JWT 24시간 폐기 시간 | 사용자 편의 vs 보안의 균형. session_revoked_at 으로 즉시 무력화 가능 | 비활성 계정 검토 |
| 비밀번호 4자 최소 (테스트 중) | 출시 후 8자+영숫자로 강화 예정 | 출시 전 적용 필수 |
