## 4. 개발·배포 절차

### 프론트엔드 (정적 사이트)
1. 코드 수정 후 `git add -A && git commit && git push origin main`
2. GitHub Pages가 1~2분 내 자동 배포
3. 배포 후 강제 새로고침(Ctrl+Shift+R) — PWA 캐시 갱신 확인

> **PC마다 최초 1회**: `git config core.hooksPath .githooks` 실행 필요.
> pre-commit 훅이 `sw.js` 캐시버전 갱신 + `FUNCTIONS.md` 재생성 + ESLint + smoke 테스트를 자동 수행합니다.

### Edge Function (Supabase)
```bash
supabase functions deploy <name> --project-ref ujxdhafzjyrglaclarwe --no-verify-jwt
```
> **`--no-verify-jwt` 플래그 필수.** 없으면 Supabase 미들웨어가 모든 요청을 401로 차단합니다.
> 배포 후 엔드포인트 직접 호출로 401 정상 응답 확인.

### 검증 명령
```bash
npm run check            # lint + smoke + 재발버그 패턴 (커밋 전 권장)
npm run lint             # ESLint (XSS 차단)
node tests/smoke.js      # 유닛 테스트
npx playwright test --project=sentinel   # 라이브 URL 스모크 (배포 후)
```

### 금지 사항
- `npm install` / `package.json` 의존성 추가 금지 (정적 사이트)
- 운영 코드에 `console.log` 추가 금지
- Supabase anon key / API 키 소스 하드코딩 금지

## 5. 보안 모델 (반드시 이해할 것)

- **서버(Edge Function `api` 프록시)가 진짜 보안 경계**입니다. service_role로 PostgREST를 호출하며 RLS를 우회하는 대신, 프록시 자체가 모든 격리를 강제합니다.
  - 모든 비-superadmin 역할에 `center_id` 강제 주입 → 타 센터 침범 불가
  - 학부모는 본인 자녀 + `parent_visible=true`만 접근, 쓰기 차단
  - 세션 무효화(강제 로그아웃·비번변경 즉시 반영) 내장
- 클라이언트 필터는 보조일 뿐, **서버가 격리를 보장**합니다.
- 모든 사용자 입력은 `escHtml()` 처리. 인라인 핸들러 JS 인자는 `jsArg()`. 신규 코드는 `data-action` 위임 권장.
- AI에 여러 아동 정보 전송 시 반드시 `madiNameMasker()` 가명화 경유.

## 8. 인계 시 주의사항 (전임자가 겪은 함정)

- **모든 ID는 문자열로 다룰 것.** `parseInt(select.value)`로 ID를 숫자 비교하면 매칭이 항상 깨지는 회귀 버그가 반복됨. 비교는 `String(a) === String(b)`.
- **PWA 캐시가 배포를 숨길 수 있음.** 디바이스 동작이 배포 후에도 안 바뀌면 코드보다 "새 코드가 실제 실행 중인가"를 먼저 의심. (현재 JS/CSS는 network-first로 대부분 해결됨)
- **KST 시간대**: `toKST()`가 getTimezoneOffset을 보정하므로 KST 기기에선 `new Date()` ≈ `nowKST()`. "시간대 버그"로 보이는 다수는 오탐.
- 스크롤/터치 버그는 JS보다 CSS(`overscroll-behavior`, `overflow:hidden`, `position:fixed` 오버레이)를 먼저 확인.
