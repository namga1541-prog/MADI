# 🔍 MADI 코드 점검

사용자가 `$ARGUMENTS` 로 **깊이**와 **범위**를 전달했다.
- 깊이 미지정 → **L2(표준)** 로 진행한다.
- 범위 미지정 → **최근 변경분**(`git diff` + 마지막 커밋)을 대상으로 한다.
- 이 커맨드는 **점검·보고만** 한다. 코드 수정은 하지 않는다(발견 후 사용자 승인 시 별도 진행).

---

## ① 점검 깊이

**L1 — 가벼움** (소규모 수정 후·커밋 전, 토큰 최소)
- `npm run check` (ESLint+smoke+패턴) 실행
- `git status` 클린·로컬=원격 동기화 확인
- **이번 변경분(diff)만** 회귀 스캔 (아래 ③-D)

**L2 — 표준** (기능 추가·수정 후, 단일 컨텍스트)
- L1 전부 +
- 변경에 닿는 도메인 파일을 FUNCTIONS.md로 위치 잡아 **로직 정독**
- 정적 무결성 4종: 인라인 핸들러 정의여부 · escHtml(XSS) · SCHEMA 컬럼정합 · 회귀 3종
- 해당 기능의 **권한 분기**(superadmin/admin/teacher/parent)와 **center_id 격리** 확인

**L3 — 철저** (베타·릴리즈 전, 전수)
- L2 전부 +
- 관련 전 파일 도메인별 정독 + **엣지케이스·동시성(lost-update)·오프라인큐·권한 매트릭스** 점검
- 라이브 배포 반영 확인 (curl로 최신 빌드 검출)
- ⚠️ 멀티에이전트가 꼭 필요하면 **"에이전트 N개·예상 토큰" 먼저 보고하고 승인받은 뒤** 실행 (자동 실행 금지)

---

## ② 공통 원칙 (항상 적용)

1. **위치 탐색은 FUNCTIONS.md 우선** → 해당 줄 ±15줄만 Read. 전체 통독 금지.
2. **보고 전 ARCHITECTURE.md "흔한 오탐 주의"와 대조** → 오탐을 결함으로 올리지 말 것.
3. **스크롤·터치 이슈는 CSS부터** (overscroll-behavior · overflow:hidden · touch-action · position:fixed 오버레이).
4. **"코드 정상 ≠ 사용자 확인"** — 정적 검증으로 못 잡는 동작 무결성은 "실기기 수동 테스트 필요"로 명시.
5. **추측 금지** — 확신 없으면 grep/Read로 근거 확보 후 보고. 근거 라인 제시.

## ③ 점검 항목 체크리스트 (도메인별)

**A. 보안**
- 모든 사용자 입력에 `escHtml()` (innerHTML 직접 대입 시 ESLint no-unsanitized 통과 여부)
- DB 접근은 `supaFetch()` 경유만 — anon key 하드코딩·직접호출 금지
- URL 식별자에 `encodeURIComponent()` 적용
- IDOR — 본인/센터 데이터만 접근하는가 (서버 필터, 클라 필터만으로 불가)
- AI 프롬프트·보고서에 **아동 실명 유출** 없는가 (가명 ○○ 처리)
- raw `e.message` 외부 노출 금지 (`_userErrMsg`/고정문구)

**B. 데이터 무결성**
- 저장이 **전체 덮어쓰기**가 아닌 **단건/배치**인가 (lost-update 회귀)
- 오프라인 큐 FIFO 불변식 (성공→제거, 실패→보존)
- limit 없는 GET → max-rows 1000 컷 위험 (페이지네이션 `_supaFetchAll`)

**C. 런타임/핸들러**
- `onclick` 등 인라인 핸들러가 부르는 함수가 **실제 전역에 정의**됐는가
- 함수 호출 전 `typeof fn === 'function'` 가드 (선택 로드 파일)
- null/빈배열/undefined 가드 (DB 미초기화 케이스)

**D. MADI 회귀 버그 클래스 (재발 이력 — 반드시 확인)**
- **childId는 문자열** — `parseInt(select.value)`로 ID 비교 금지 (String 비교)
- **날짜에 `toISOString().slice(0,10)` 금지** — KST 새벽 하루 어긋남. `ymd(nowKST())` 사용
- **index.html DOM 박제** — 런타임 DOM·실데이터가 정적 소스로 커밋됐는가
- PWA 캐시 — 새 코드가 실제 디바이스에서 실행되는가 (배포 후 안 바뀌면 캐시 의심)

**E. DB/SCHEMA 정합**
- select/POST 컬럼이 **SCHEMA.md에 실재**하는가 (없는 컬럼 → 400, 인증실패처럼 보임)
- `madi_users`에 `status` 등 미존재 컬럼 주입 없는가
- flat 테이블(`madi_activities`) vs 제네릭 `data` 래핑 혼동 없는가

**F. UX/접근성**
- 빈 상태·로딩 상태 안내 존재
- 이미지 `alt`, 모달 `role/aria-modal`, 토스트 `aria-live`
- 터치 타깃 충분(모바일), 가로 오버플로 없음

**G. 성능**
- 30초 폴링 무변경 시 풀렌더 스킵(해시 비교)
- 불필요한 반복 렌더·중복 네트워크 호출

## ④ 출력 형식 (이대로 보고)

각 발견 항목을 **심각도 순**으로:

> **[심각도]** `파일:라인` — **증상 한 줄**
> - 원인: …
> - 영향: (크래시/데이터유실/보안/오작동/경미)
> - 재현: (어떤 조건에서)
> - 수정안: …
> - ⚠️오탐의심: (확신 낮으면 표기)

심각도 기준:
- **CRITICAL**: 크래시·데이터유실·보안유출 — 베타 차단
- **HIGH**: 핵심 흐름 오작동 — 베타 차단
- **MEDIUM**: 부분 오작동·UX 결함 — 베타 후 가능
- **LOW**: 경미·권고

마지막 줄에 **"자동검증 통과 ≠ 실기기 동작 확인"** 과 남은 수동 테스트 영역을 명시한다.
